# 車検 事前カルテ Webアプリ（GAS）

自動車整備工場の待合室に置いたQRから、お客さま自身がスマホで「車の困りごと」を入力。
フロントマンがその場で確認し、松竹梅の高単価提案につなげるための営業支援ツールです。

**マルチテナント設計：システムもスプレッドシートも当社が1つだけ持ち、工場は `?shop=` で区別します。**
工場ごとにコピーは作りません。当社が1回直せば全工場に反映されます。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `コード.gs` | `doGet` ルーティング／保存・取得関数／初回セットアップ |
| `form.html` | お客さま入力画面（`?shop=xxx`） |
| `desk.html` | フロント確認画面（`?shop=xxx&view=desk`） |

> ⚠️ これはリポジトリ既存の「スマート営業報告システム」（ルートの `コード.gs` / `index.html` / `dashboard.html`）とは**別のGASプロジェクト**です。混在させず、この `shaken/` 配下の3ファイルを1つの新しいGASプロジェクトに貼ってください。

## セットアップ手順

1. 新しい Google スプレッドシートを1つ作る（当社用に1つだけ）。
2. 拡張機能 → Apps Script でエディタを開く。
3. 以下の3ファイルを作成し、中身を貼り付ける：
   - スクリプト `コード.gs`
   - HTML `form`（`form.html` の中身）
   - HTML `desk`（`desk.html` の中身）
4. エディタで **`setup` 関数を1回だけ実行**する（初回だけ権限承認あり）。
   → 「回答」「工場マスタ」シートが自動で作られます。
5. 「工場マスタ」シートに工場を登録（例）：

   | 工場ID | 工場名 |
   |---|---|
   | tanaka | 田中モータース |

6. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」
   - 実行ユーザー：自分
   - アクセスできるユーザー：**全員**（お客さまがログイン無しで開けるように）
   - デプロイして発行された `/exec` URL を控える。

## URL とQRの運用

- **お客さま入力用（QRにする）**：`https://……/exec?shop=tanaka`
- **フロント確認用（工場のPC/タブレットで開く）**：`https://……/exec?shop=tanaka&view=desk`

工場が増えたら **「工場マスタ」に1行足す＋QRを1枚作るだけ**。コードは触りません。

## 個人情報の方針

- 氏名は任意（呼び名OK・空欄可）／ナンバーは**下4桁のみ**／車種・走行距離は任意。
- その場の提案に使うツールで、長期名簿としては使いません。
- 入力画面フッターに「入力内容は車検のご提案にのみ使用します」を明記。

## 困りごと → 提案マッピング（フロント確認画面にのみ表示）

| id | お客さまに見せる言葉 | 裏で紐づく提案 | 松竹梅 |
|---|---|---|---|
| ac | エアコンが臭う・効きが弱い | Dr.Clean（MB-CL1 内部洗浄）＋ プレミアムフィルター PC-518S | 竹 |
| power | 加速がもたつく・パワー不足 | BG107 RF-7 オイル添加剤 | 松 |
| fuel | 燃費が落ちた気がする | BG107 RF-7 オイル添加剤 | 松 |
| heat | 水温・オーバーヒートが心配 | BG546（Super Cool）クーラント ※次回交換までLLC性能を維持 | 松 |
| brake | ブレーキの効き・キーキー音 | K4PAD プレミアムパッド K-796WK | 竹 |
| none | 特に気になることはない | 標準の竹を丁寧にご案内 | — |

> **表現の注意**：BG546は「次回交換までLLC性能を維持」する製品。「交換が不要になる」ではありません。この表現を守っています。

## フロント確認画面の動き

- その工場の**当日ぶん**を新しい順に表示。
- **20秒ごとに自動更新**（Slack通知の代わりに、この画面で完結）。
- お客さんの言葉のタグ＋裏の商材提案＋「まず松から見せて、響いた項目を竹に足す」ガイドを表示。
